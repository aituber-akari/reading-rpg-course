第1部 一瞬の行動 ／ 第2章

障害を乗り越える

【ダミー】同じ崖の前に立っても、登攀の技能がある人、ロープを持つ人、蔦を見つけた人では、取れる行動が違う。この章では、その違いをデータとして表す。

  • 目安 2〜3時間
  • TypeScript：Set、型の合成
  • Git：ブランチ

今回作るもの

【ダミー】技能・所持品・環境の組合せから、実行できる行動の一覧を求めるプログラムを作る。完成すると、次のようなログが出る。

期待される動作：

  • 登攀の技能が足りれば、直接登る行動が候補に入る。
  • ロープと固定点の両方があれば、ロープを使う行動が候補に入る。

出発点

【ダミー】第1章の完成版から始める。前章との差分は次のとおり。

ファイル変更内容
src/actions.ts新規行動の定義（前提条件・効果・コスト）
src/world.ts変更環境に「固定点」「蔦」を追加

演習

【ダミー】動作例を見る → サンプルを改造する → 機能を自力で追加する → 完成版と照合する、の順に進める。

必須演習 2-1 行動の前提条件を書く

編集するファイル：src/actions.ts

【ダミー】「ロープで登る」行動に、ロープの所持と固定点の存在という2つの前提条件を加える。使う構文は必要な知識を参照。

必須演習 2-2 実行できる行動を列挙する

【ダミー】状態を受け取り、前提条件を満たす行動だけを返す関数 availableActions を書く。

注意

【ダミー】Set を JSON.stringify すると空のオブジェクトになる。ログに出すときは配列に変換すること。

発展演習 2-A 新しい解決法を足す

【ダミー】「魔法で浮く」行動を追加し、技能の組合せによって新しい突破手段が現れることを確かめる。必須ではない。

必要な知識

Set：重複のない集まり

【ダミー】所持品や地形の特徴のように、「あるか、ないか」だけを問う集まりには Set を使う。

文献コラム

アフォーダンス理論との対応

【ダミー】ギブソンは、環境が動物に提供する行為の可能性をアフォーダンスと呼んだ。この章のデータ構造は、その一部を次のように写し取っている。

理論の概念この章の実装
アフォーダンス
前提条件を満たした行動（availableActions の戻り値）
環境の性質
地点の特徴の集合（place.features）
行為者の能力
技能レベルと所持品（skills、items）

【ダミー】ただし、ここでは行為の可能性をあらかじめ列挙しており、知覚による発見は扱っていない。この違いは第5章以降で再び取り上げる。

参考：Gibson, J. J. (1979). The Ecological Approach to Visual Perception. Houghton Mifflin.

動作確認

  1. 【ダミー】npm run dev を実行する。
  2. 所持品からロープを外して、もう一度実行する。

確認する観点：持ち物を変えたとき、候補の行動が変わること。

テスト

  • 【ダミー】技能が足りないとき、直接登る行動が候補に含まれない。
  • ロープと固定点がそろったときだけ、ロープを使う行動が候補に含まれる。
